## 第 0 步：确认你的环境

你只需要 **一个现代浏览器**（Chrome / Edge / Firefox / Safari 都行）。

- ❌ 不需要装 Node.js
- ❌ 不需要装 Python（除非你要用采集器）
- ❌ 不需要装数据库、不需要搭服务器
- ❌ 不需要联网（除了 AI 功能）

**为什么这么简单**：这个项目刻意做成了「双击就能跑」的纯前端应用，数据存在你自己的浏览器里。

---

## 第 1 步：把项目拿到本地

### 方式 A：用 Git（推荐，方便以后更新）

```bash
git clone https://github.com/xiaojiao143/job-hunter-workbench.git
```

### 方式 B：直接下载压缩包（不想装 Git 就用这个）

1. 打开仓库页面
2. 点绿色的 **Code** 按钮 → **Download ZIP**
3. 解压到你喜欢的目录（**路径里最好不要有中文和空格**，偶尔会有怪异问题）

解压/克隆后，你会看到这样的结构：

```
job-hunter-workbench/
├── 求职猎手工作台/     ← 应用本体，你要打开的就是这里面的 index.html
├── _打包工程/          ← 打包成 exe 的工装，普通用户不用管
└── README.md
```

---

## 第 2 步：打开它

进入 `求职猎手工作台` 文件夹，**双击 `index.html`**。

浏览器会打开，你应该看到左边一排导航（岗位库 / 采集岗位 / 投递看板 / 面试管理 …），右边是主区域。

> **打不开怎么办？**
> - 如果你是双击后看到一堆代码，说明被文本编辑器抢了默认程序 → 右键 `index.html` → 打开方式 → 选 Chrome/Edge
> - 如果页面空白 → 按 F12 看 Console 有没有红色报错，把报错内容发到 [Issues](../../issues)

### 第一次打开是什么状态

**空的**。没有岗位、没有投递、没有简历。这是正常的——数据从零开始积累。

## 第 3 步：导入示例数据逛一圈

先看看它长什么样，再决定要不要用。

1. 点左下角 **⚙️ 设置**
2. 找到「数据备份」区域
3. 点 **导入**
4. 选择 `求职猎手工作台/demo-data/demo-backup.json`

导入成功后你会看到 6 条虚构岗位、2 条投递记录、1 场面试、1 份简历素材。

**建议按这个顺序逛**：

| 去哪 | 看什么 |
|---|---|
| 岗位库 | 卡片布局、筛选条、合适度分数 |
| 投递看板 | 拖拽卡片改变状态（待投 → 已投 → 约面 …） |
| 面试管理 | 轮次安排、备面材料入口 |
| 待跟进 | 跨表汇总是怎么把这些串起来的 |
| 公司背调 | 红黄绿灯分级 |
| 数据仪表盘 | 求职漏斗、状态分布、薪资分布 |

> ⚠️ 示例数据全部虚构。逛完后到 **设置 → 数据备份 → 清空**，再开始录你自己的。

## 第 4 步：换成你自己的数据

有三种进数据的方式，从省事到强大：

### 方式 1：手工录入（最直接）

岗位库 → 右上角 **新增岗位** → 填标题/公司/薪资/JD → 保存。

适合：岗位不多（几十个以内），或者只想先试几个。

### 方式 2：导入 CSV / JSON

如果你已经有一份岗位表（Excel 导出的 CSV 就行），可以批量导入。

岗位库 → **导入** → 选文件。

> 导入器对列名的识别比较宽松（"岗位名称"/"职位"/"title" 都能认），但如果你的表头特别不同，可能需要在 Excel 里先改一下列名。

### 方式 3：本地采集器自动拉（需要 Python，进阶）

见 [第 6 步](#第-6-步可选启动本地采集器)。

## 第 5 步（可选）：接入 AI

不配 AI 也能用全部核心功能（岗位管理、看板、筛选、背调、仪表盘）。配了之后多出：

- JD 一键解析（自动填薪资/技能/职责）
- 简历匹配打分（逐条告诉你缺什么）
- 打招呼话术生成
- 面试题预测、模拟面试
- AI 求职助手对话

### 怎么配

1. **设置 → ① 大模型接口**
2. 填三项：
   - **接口地址**：比如 `https://api.deepseek.com/v1`（只填到 `/v1` 即可，不用带 `/chat/completions`）
   - **API Key**：去你选的服务商控制台申请
   - **模型名**：比如 `deepseek-chat`
3. 点 **测试连通**，看到成功提示就配好了

### 关于花费

- 按 token 计费，一次 JD 解析通常几分钱人民币
- 界面上每次 AI 操作都会先给你**预估花费**，确认后才真正调用
- Key 只存在你本机浏览器里，请求直接发往你填的服务商，不经过任何中间服务器

## 第 6 步（可选）：启动本地采集器

> ⚠️ **先说清楚**：这是**可选组件**，用于把你**自己账号下**的岗位信息整理到工作台里。
> 使用前请自行确认目标平台的服务条款。详见 [README 的合规声明](../README.md#合规与免责)。

### 需要什么

- Python 3.9+（安装时记得勾选 "Add Python to PATH"）
- 一个 Edge 或 Chrome 浏览器

### 怎么启动

```bash
cd 求职猎手工作台
python 采集器/server.py
```

然后浏览器会自动打开 `http://127.0.0.1:8738/`。

**注意**：从这个地址打开的页面，才带访问令牌，才能调用采集接口。
直接从 `file://` 双击打开的 `index.html` **用不了采集功能**（这是刻意的安全设计）。

### 怎么停

- 页面右上角有停止按钮
- 或直接关掉命令行窗口

## 日常怎么用：一个求职周期的推荐流程

这是我自己用下来最顺的路径，供参考：

### ① 收岗（每天 10 分钟）

- 采集器跑一批，或手工录入几个
- 进 **岗位库**，按城市/薪资/合适度筛掉明显不合适的
- 对中意的点开看看 **避坑雷达**（扫描 JD 里的收费/外包/话术红旗）

### ② 投递（批量处理）

- 挑 10-20 个进 **投递看板**的「待投」
- 投完的拖到「已投」
- 给每条记一句 `note`（比如"HR说三天内回复"）——**这一句以后会救你**

### ③ 跟进（每周 2 次）

- 打开 **待跟进** 页
- 它会自动列出：投了 N 天没回音的、面试完没复盘的、约了面试但快到的
- 按提示处理，处理完的状态会回去

### ④ 面试准备

- 面试管理 → 新建轮次
- 点 **备面材料** → AI 帮你生成自我介绍、预测问题
- 面完回来填 **复盘**（记下被问了什么、哪里答得不好）

### ⑤ 决策

- 到 offer 阶段，用 **岗位对比** 横向比较
- 用 **公司背调** 过一遍风险
- 仪表盘看整体漏斗：投了多少、转化率多少、卡在哪一环

### 贯穿全程：每周导出一次备份

设置 → 数据备份 → 导出。存到你网盘或 U 盘。**浏览器清缓存会丢数据**。

## 数据在哪、怎么备份、怎么换电脑

### 数据存在哪

**浏览器的 `localStorage`**，键名 `jobhunter.db.v1.<账号名>`。

- ❌ 不在服务器
- ❌ 不在项目文件夹里
- ✅ 只在你这台机器的这个浏览器里

### 这意味着什么

| 场景 | 后果 |
|---|---|
| 清浏览器缓存/数据 | **数据全丢** |
| 换浏览器 | 数据不在（要手动导入） |
| 换电脑 | 数据不在（要手动导入） |
| 用隐私/无痕模式 | 关掉窗口就没 |
| 多人共用一台电脑 | 用「账号」功能隔离（本机多账号沙箱） |

### 所以：定期导出

**设置 → 数据备份 → 导出**，得到一个 JSON 文件。这就是你的全量备份。

> 建议每周导一次，或者每次大批量改动后导一次。

### 换电脑 / 换浏览器

1. 老机器：导出 JSON
2. 新机器：打开项目 → 设置 → 数据备份 → 导入 → 选那个 JSON

### 导出里有什么、没有什么

- ✅ 岗位、投递、面试、简历素材、背调、AI 对话
- ⚠️ API Key **默认被抹掉**（出于安全），恢复后要重新填一次
- ⚠️ 采集器里的简历原件（`采集器/data/resume/`）不在里面，需要单独拷

## 常见问题

### Q：双击 index.html 出现乱码 / 一堆代码？

浏览器没正确识别。右键 → 打开方式 → 选 Chrome 或 Edge。
另外确认文件编码没被编辑器改过（正常是 UTF-8）。

### Q：数据能同步到手机吗？

不能。这是「本地优先」的代价。换设备靠导出/导入 JSON。
移动端只做了基础适配，主要面向电脑使用。

### Q：能存多少岗位？

浏览器 localStorage 一般 5MB 上限，大约 2,000-3,000 条岗位。
快满了会提示你。到时候导出分库，或删掉不看的旧岗位。

### Q：AI 一直转圈 / 报错？

按顺序排查：
1. 设置里 **测试连通** 能不能过
2. 接口地址是不是只填到了 `/v1`（别带 `/chat/completions`）
3. Key 有没有余额
4. F12 → Network 看请求状态码

### Q：采集器页面打得开，但点按钮都失败？

大概率是「来源不在白名单」——说明你不是从 `http://127.0.0.1:端口/` 打开的页面。
解决：关掉页面，重新双击 `启动采集器.cmd`，用它自动打开的窗口操作。

### Q：我改了代码，怎么让改动生效？

刷新页面（Ctrl+F5 强制刷新）。
如果是改 `js/` 或 `css/`，改完记得同步打包副本（见 [CONTRIBUTING](../CONTRIBUTING.md)）。

### Q：能打包成 exe 发给朋友吗？

可以，`_打包工程/` 里有完整的 PyInstaller 工装。
但那属于进阶用法，而且**不要连你的数据一起发出去**。
