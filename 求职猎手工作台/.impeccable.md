# 设计上下文 · 求职猎手工作台

> impeccable / frontend-design 类设计工具读这个文件。
> 目的：防止工具"读代码库猜意图"，把你的 B 端工具改成落地页。

## Target audience（谁在用）

**一个正在密集求职的个体求职者。** 不是设计师、不是开发者。

使用情境：
- 坐在电脑前，一次连续工作 1–3 小时（批量筛岗 + 投递 + 跟踪）
- 心理状态：**焦虑 + 高度专注**。他要的是"尽快找到能投的岗位"，不是"欣赏设计"
- 可能的设备：Windows 笔记本，`file://` 双击打开（无服务器），也可能从采集器 8738 访问

## Use cases（核心任务，按频次）

1. **批量筛岗**（最高频）— 从 BOSS 采集回来几百条，快速按合适度/城市/薪资过滤掉不合适的
2. **投递跟踪** — 记住哪些投了、哪些该跟进、哪些已过期
3. **简历匹配诊断** — 看这份简历跟这个岗位差在哪
4. **公司背调** — 判断这家公司值不值得去（接 offer 前）
5. **面试管理** — 轮次、待跟进、复盘

**关键洞察**：任务 1 是「扫读」不是「阅读」。用户在一屏内比较多个岗位卡片，靠**位置、颜色徽章、数字**快速判断，不读长文案。

## Brand personality / tone

**克制、可靠、信息密度优先。像一把好用的工具，不像一个想讨好你的产品。**

具体表现：
- 数字和状态比装饰重要（合适度分数、背调灯、投递状态）
- 不用营销语气，不喊口号，不做情绪化引导
- 蓝色 `--brand: #1d4ed8` 是唯一强调色，用在"可点击/当前选中/主操作"，不滥用
- 语义色（绿/黄/红）**只用于状态判断**，绝不用于装饰

## 必须遵守的项目约定（来自既有前端铁律）

1. **信息密度 > 视觉留白**。卡片布局是**有意的场景决策**，服务于"一屏扫完 N 个岗位"。不要为了"呼吸感"拆散它。
2. **动效必须克制**。已实现全局 `prefers-reduced-motion` 降级。**不要新增**回弹/弹跳/弹性缓动，不要动画化 `width/height/top/left`。
3. **焦点环必须保留**。全站零 `outline: none` 是硬约定，不要引入 `outline: none` + 自定义 box-shadow 的写法。
4. **每个能关的功能必须有关闭的地方**，且有测试真点它。
5. **渐进式披露**优先于平铺信息。空状态要有教育意义。
6. **移动端可以简化布局但不得隐藏关键功能**。

## 明确不要做的事

- ❌ 改成落地页/作品集风格（大标题、hero 区、留白堆叠）
- ❌ 引入 Inter / Roboto / Arial（当前系统字体栈 + Cascadia Mono 是有意的）
- ❌ 紫蓝渐变、渐变文字、霓虹点缀
- ❌ 毛玻璃（`backdrop-filter`）——当前零使用，不要引入
- ❌ 卡片套卡片（`.card` 内再套 `.card`）
- ❌ 提高圆角、增加通用 box-shadow 堆叠
- ❌ 移动端 `display: none` 藏功能
- ❌ 纯黑 `#000` / 纯白 `#fff` 作为大面积背景

## Token 约定

- 唯一来源：`css/app.css` 顶部 `:root`（浅色 39 个变量）与 `html[data-theme="dark"]`（深色覆盖）
- 令牌**语义化命名**：`--text-2` `--muted` `--ok-soft` `--line-2`，不是 `--gray-500`
- 硬编码色仅允许两类：语义色的 `-soft` 派生、深色主题覆盖令牌本身

## 无障碍基线（已达成，别退步）

- 正文对比度 ≥ 4.5:1（WCAG AA），大字号/图标 ≥ 3:1
- 交互元素绑在语义化 `<button>`，不用裸 `<div onclick>`
- 焦点指示用 `:focus-visible`
- 已实现 `prefers-reduced-motion: reduce` 全局降级

## 技术约束

- **纯手写 CSS**，不依赖 Tailwind CDN（保证 `file://` 离线双击可用）
- 无构建步骤，无 npm。`index.html` 直接双击打开
- JS 是 ES5+/原生，无框架。29 个模块挂在 `window.Views`
- 单页应用，`App.go()` 整页重画；弹窗内**只就地重画**，禁 `App.refresh()`
- 焦点保持靠 `[data-focus-key]`（重画后是新节点，不能用 id）
