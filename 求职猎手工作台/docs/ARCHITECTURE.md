# 架构设计

> 本文说明这个项目**为什么这么组织**，不只是"有哪些文件"。

## 一句话架构

**单页应用 + 纯函数式数据层 + 手动重画。** 没有框架，状态变更后由 `App.go()` 整页重画；弹窗内只就地重画。

```
index.html
  └─ 按固定顺序加载 32 个 <script>
       ├─ 底层：utils.js → store.js → account.js
       ├─ 能力：ai.js / charts.js / export.js / components.js
       ├─ 领域：job-taxonomy / job-picker / geo / company-check
       │        job-match / job-score / pitfall / ai-collect
       │        apply-boss / collect-prefs
       ├─ 页面：view-*.js（12 个，注册到 window.Views）
       └─ 外壳：app.js（路由 / 导航 / 主题 / 提醒）
```

**加载顺序即依赖顺序。** 这是刻意的简化：没有模块系统，所以用 `<script>` 顺序表达依赖。`store.js` 依赖 `utils.js` 的 `U.*`，页面依赖 `store` 和 `components`。

## 五层职责

### 1. 工具层 `utils.js`（808 行）

纯函数，无状态。DOM 工厂、日期、数字、数组、字符串转义、下载、弹窗、Toast、菜单、焦点保持。

**关键设计：`el()` DOM 工厂**

```js
el('div', { class: 'card', onclick: fn }, [child1, child2])
```

避免手写 `createElement` / `appendChild` 的重复代码。第二个参数的 `text:` 是纯文本、`html:` 是受信任 HTML 通道——**外面数据必须走 `text:` 或先 `U.esc()`**。

**关键设计：焦点保持**

整页重画会销毁 DOM 节点，用户正在输入的光标就丢了。解决办法：给输入框标 `data-focus-key`，重画前记录 `document.activeElement` 的 key 和 selection，重画后按 key 找回节点并恢复。

### 2. 数据层 `store.js`（2,208 行）

**整个项目最核心的文件。** 它是唯一的写库入口，负责：归一化、持久化、跨标签页同步、导入导出、统计。

**关键设计：重建式白名单**

```js
function normJob(j) {
  return {
    id: ..., title: ..., company: ..., salaryMin: ...,
    // ⚠️ 只返回这里列出的键
  };
}
```

**为什么不是补充式？** 因为补充式（`Object.assign(j, defaults)`）会让脏字段永久驻留，越滚越大；重建式保证每次加载出来的对象形态一致。

**代价**：写了字段但没加进白名单 → 静默丢失。这是本项目踩过最多次的坑（注释里有 6 处事故记录）。所以约定：**凡是 `updateX` 要写的字段，`normX` 必须有对应一行**，并由测试兜底。

**关键设计：迁移函数 `migrate()`**

老版本数据加载时统一过一遍 `migrate()`，补默认值、丢未知字段、修字段形态。所有历史数据格式变更都靠它兼容。

**关键设计：跨标签页同步**

监听 `storage` 事件，对端写盘后本页就地换内存（不 reload，避免对刷）。这里有个关键细节：**必须做合并而不是整份替换**，否则会吃掉本页未落盘的编辑（防抖窗口 260ms 内）。

### 3. 能力层（可独立测试的纯逻辑）

| 模块 | 职责 | 特点 |
|---|---|---|
| `job-score.js` | 五维合适度打分（方向/关键词/薪资/经验/通勤） | 纯逻辑，可单测 |
| `job-match.js` | 自然语言搜索解析 + 简历匹配 | 纯逻辑 |
| `pitfall.js` | JD 避坑扫描（本地规则引擎） | **不联网、不调模型** |
| `company-check.js` | 背调风险分级 | 纯逻辑 |
| `export.js` | CSV / Excel / JSON 导入导出 | 含薪资解析等脏活 |
| `ai.js` | 模型调用（流式 + JSON 修复） | 用户自配 Key |

**这些模块的共同点：不碰 DOM（除个别展示函数），所以能在 Node 里直接测。** 这是 2,470 条断言能存在的基础。

### 4. 页面层 `view-*.js`（12 个）

每个页面导出 `{ title, render, ... }` 并注册到 `window.Views.<id>`。

**约定**：
- `render(root, params)` 负责画整页
- **弹窗内只就地重画**，禁止调 `App.refresh()`（会销毁弹窗、丢失用户输入）
- 回调顺序：**先落值、再关窗**（`U.confirm` / `U.openModal` 的 `onClose` 是异步的）

### 5. 外壳 `app.js`（597 行）

路由（hash 驱动）、侧边栏计数、主题切换、面试提醒、备份提醒、版本变更提示、全局 AI 唤起。

## 可选后端：本地采集服务

`采集器/server.py`（3,071 行，Python 标准库）是一个**本地 HTTP 服务**，只监听 `127.0.0.1`。

**安全设计**（本项目最值得看的一段）：
1. **Origin 白名单**：只允许 `http://127.0.0.1:<端口>`，**不含 `'null'`**（`file://` 页面的 Origin 是 null，放开等于对任何本地页面开放）
2. **令牌鉴权**：`X-JH-Token` 头或 `?k=` 查询参数，用 `hmac.compare_digest` 常量时间比较
3. **令牌只注入同源页面**：`_serve_static` 只有 `_is_same_origin()` 为真时才把 token 写进 HTML
4. **静态白名单**：只伺服 `index.html` / `favicon.ico` / `js/` / `css/`，**不伺服 `.json` / `.md`**（否则全量岗位数据和登录态可被匿名读走）
5. **请求体上限前置校验**：先判 `Content-Length` 再读，防止伪造超大长度或负数挂死线程

**核心功能**：任务单例管理、暂停/熔断、日配额、静态文件服务、简历上传解析。

## 打包工程 `_打包工程/`

把应用打包成 exe 的工装。**它有一份前端副本 `src/`**，因为 PyInstaller 需要真实文件而非运行时路径。

**已知风险**：副本会漂移（源码改了但副本没同步）。为此有 `sync_src.py`：
- `--check`：只校验，不一致 exit 1
- `--apply`：同步（先备份）

`pack_main.py` 里内置**双重闸门**：闸门 1 调 `sync_src.py --check`，闸门 2 校验关键文件存在性。任一失败即中止出包。

> ⚠️ 历史教训：闸门曾存在但白名单不全（`js/` 阈值只有 `<5`、关键模块清单漏了 `ai-collect.js`），导致"闸门通过但漏了模块"。现在的白名单已修正。

## 为什么这些决策值得保留

| 决策 | 代价 | 收益 |
|---|---|---|
| 无框架 | 手写 DOM/状态/路由 | `file://` 双击可跑、零安装 |
| 重建式白名单 | 写字段易漏 | 数据形态永远一致、无脏字段累积 |
| 整页重画 | 性能不如虚拟 DOM | 逻辑极简、无状态同步 bug |
| 前端副本 + 同步脚本 | 需要记得跑 sync | PyInstaller 能正常工作 |
| 本地优先 | 无多设备同步 | 隐私、离线、无服务器成本 |
