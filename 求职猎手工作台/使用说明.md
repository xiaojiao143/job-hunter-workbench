# 求职猎手工作台 · 使用说明

一个**纯本地**的求职管理工具。双击 `index.html` 就能用，不用装软件、不用起服务器、不用注册网络账号。

数据全部存在你自己的浏览器里（localStorage），AI 请求由你的浏览器**直连模型服务商**，不经过任何第三方中转。

> **先把两件事分清**（评审里最容易混的一句「零依赖」）：
> - **工作台本体**（岗位库 / 投递看板 / 面试 / 统计 / AI 解析）—— 真·零依赖。双击 `index.html` 即用，不联网也能开。
> - **「📡 采集岗位」这一页** —— 需要本机的**采集器小服务**：Python 专用虚拟环境 + `boss-crawler` 技能 + 一个真实 Edge 窗口 + BOSS 扫码登录。
>   这是**另一条链路**，缺任何一环采集就用不了，但**完全不影响**本体。

> **本机多账号**：侧边栏底部有个账号区，可以建多个账号，每个账号一份独立数据（换号即换数据、换回即恢复）。这是本机数据沙箱，不是网络登录，密码仅防误操作。详见第十节。

## 一、30 秒上手

**最快的一条路（不用采集器）**：

1. 双击 `D:\AIshuju\BOSS\求职猎手工作台\index.html`
2. 建议用 **Chrome / Edge** 打开
3. 左侧点「⚙️ 设置」→ 填模型 API Key（见第二节）
4. 回左侧「🗂️ 岗位库」→ 右上角「＋ 导入 BOSS 岗位」→ 粘贴岗位文字 → 「🤖 AI 解析岗位」
5. （可选但很省事）在「🗂️ 岗位库」里点筛选栏上面的「**⚙ 我的求职偏好**」，展开就是一块折叠面板，
   填上**目标城市 / 薪资底线 / 不能接受的点**（**改完即时生效，没有保存按钮**）
   → 再点一下「**⚙ 按我的偏好筛选**」；或者干脆在搜索框里敲「**杭州 运营 15k 不要外包**」
6. 库里的岗位多了之后，点右上角「**🤖 按简历推荐**」批量打匹配分，跑完自动按分排序，
   「🏆 高匹配」胶囊和「⏰ 待跟进」页的「高匹配还没投」就都有内容了

就这样。第一次打开是空的，可以先到「设置 → 数据与备份 → 载入示例数据」看看长什么样。

**常用快捷键**（侧边栏底部也有一个「⌨ 快捷键 / 帮助」按钮，随时能查）：

| 键 | 作用 |
|---|---|
| `Ctrl + K` | 唤起 / 收起 AI 快速问答（和右下角 💬 一样） |
| `Enter` | 快速问答输入框里直接发送 |
| `Esc` | 关闭最上层的弹窗 |

**想省掉一条条复制粘贴**：双击 **`启动采集器.cmd`**（在同一个文件夹里）。它会起一个本机小服务 + 打开工作台，左侧就多出「📡 采集岗位」这一页，能一次捞一批岗位回来。见第 2 节。

**不想一直开着一个黑窗口**：双击 **`后台启动采集器.vbs`** —— 采集器在后台静默跑（无黑窗口），浏览器照常自动打开；不想要了双击 **`后台停止采集器.vbs`** 一键停掉。两条路效果一样，区别只在「要不要那个黑窗口」。

**最省事：放两个图标到桌面**：双击 **`创建桌面快捷方式.vbs`** 一次，桌面就多出两个带图标的快捷方式 ——

| 桌面图标 | 双击后 |
|---|---|
| **求职猎手工作台** | 采集器已在跑 → 只打开页面；没在跑 → 静默起服务再打开页面（等价于上面的「后台启动采集器」） |
| **停止采集器** | 停掉后台采集器（等价于「后台停止采集器」） |

图标用的是本目录的 `favicon.ico`（蓝底圆角 + 白色「猎」，和网页左上角一致的配色）。生成器**可以重复运行**：每次先删同名旧快捷方式再建，跑几遍都不会叠出两个；桌面被 OneDrive 重定向过也能找对地方（用系统 API 取桌面路径，不写死 `%USERPROFILE%\Desktop`）。要静默跑（不弹提示框），先设环境变量 `JH_QUIET=1`，结果会写进 `采集器\data\shortcut-result.txt`。

> **启动会给你回话**（不用再猜「它到底起没起」）：
> - **起好了** → 弹一句「采集器已启动 ✅ 端口 8738」，并打开工作台页面
> - **已经在跑了** → 弹「已经在运行（端口 8738）」，**只打开页面、不会重复起一个服务**
>   （以前每双击一次就多一个服务 + 多一个标签页，现在先探活再决定）
> - **起不来** → 弹一个带**原因**的框，原因按优先级取：`status.json` 的 `error` →
>   `server.log` 尾部 → 启动输出；并附上日志路径，不再静默失败。
>
> **停止以「端口真的空出来」为准**（不是「脚本说停了」）：
> - 停的是**整棵进程树**（Windows 上 venv 的 `python.exe` 会转起一个真解释器，
>   一个服务 = 两个进程；只杀子进程会留下父进程赖着，于是下次探活命中残留、看起来「改了没反应」）。
> - 杀完复验 8738-8740：**全空**才弹「已停止」并清理痕迹；**还占着**就明确告诉你哪个端口没放开，
>   并保留 `collector.pid` / `collector.port` 方便排查。
>
> 运行痕迹都在 `采集器\data\`：`status.json`（启动结果与失败原因）、`collector.port`（实际端口）、
> `collector.pid`（**根进程**号，停止脚本据此 `taskkill /F /T` 连子树一次收掉）、`stop-result.txt`（停止结果）。

> 两条路的区别只有「岗位从哪来」。后面的 AI 匹配、投递跟踪、面试管理、数据统计完全一样。

## 二、配置 AI（必做一次）

打开 **设置 → ① 大模型接口**：

| 项 | 说明 |
|---|---|
| 服务商预设 | 点了自动填好地址和模型名，共 6 个可选 |
| API 地址 | OpenAI 兼容端点，程序会自动补 `/v1` 和 `/chat/completions` |
| API Key | 你自己去服务商官网申请，**只存在你本机浏览器里** |
| 模型名 | 比如 `deepseek-chat`、`qwen-plus`、`glm-4-plus` |

**内置预设**（都是国内可直连的）：

- **DeepSeek**（默认推荐）· `https://api.deepseek.com/v1` · 便宜、兼容 OpenAI
- 通义千问（阿里云 DashScope）· 新用户有免费额度
- 智谱 GLM · 也有免费额度
- 月之暗面 Kimi · 长文本能力强（粘超长 JD 时舒服）
- 硅基流动 · 聚合平台，模型多
- **本地 Ollama** · `http://localhost:11434/v1` · 完全离线，Key 随便填（如 `ollama`）

填完点 **「测试连通（不花钱）」** —— 它只发一个 1 token 的请求，确认地址、Key、模型名都对。

> 💡 「🤖 快速选择服务商」按钮点了会**同时**改地址和模型名，不用手填。

## 三、十一个页面怎么用

### 1. 🗂️ 岗位库（核心）

**导入岗位** —— 右上角「＋ 导入 BOSS 岗位」，两种方式：

- **粘贴岗位文字（推荐）**：在 BOSS 岗位详情页 `Ctrl+A` 全选 → `Ctrl+C` → 粘进来。乱七八糟的导航文字 AI 会自己忽略。
  - 填了岗位链接的话，以后在详情页能一键跳回 BOSS。
  - 只想复制重点也行：岗位名 + 薪资 + 公司 + 地点 + 职责 + 任职要求。
- **手动填写**：不想用 AI（或没配 Key）时用。

两个按钮的区别：
- 「🤖 AI 解析岗位」→ 调模型拆成结构化字段（公司/岗位/行业/地点/远程/薪资/年终奖/福利/职责/硬性要求/风险标记）
- 「不用 AI，直接存原文」→ 用正则粗猜几个字段，原文完整留着，以后想解析再解析

**页面结构**：
- 顶部统计条：**在库岗位**（不含归档）/ **收藏**（不含归档）/ **还没投的** / **已归档** 四个数
  - 「在库岗位」以前叫「岗位总数」，但归档后它会变小甚至归零，看着像岗位丢了 —— 所以改了名，归档数单独一项展示
- 筛选栏（关键词搜索 + 来源 + 状态 + 薪资 + 排序 + 「**▼ 更多筛选**」）
  - 筛选栏以前一屏堆了十几个控件（下拉 + 复选框 + 偏好面板 + 快捷胶囊 + 合适度条 + 标签），
    页面太长。现在**默认只留最常用的一行**（关键词 / 来源 / 状态 / 薪资 / 排序），
    其余收进「**▼ 更多筛选**」折叠面板，点一下展开 / 再点收起，折叠状态会记住。
  - 「更多筛选」按钮上有个小数字角标，提示里面当前激活了几个条件（区/商圈/合适度/收藏/归档/偏好/快捷/标签）。
- **筛选条件汇总条**：只要筛了任何条件，筛选栏下面会出现一条
  「已筛选：关键词：运营 · 薪资：10-20K · 只看收藏 　✕ 清除全部」。
  点任意一个条件的小 ✕ 就摘掉它，点右边「✕ 清除全部」一次清空。
  > 为什么加它：以前选完四五个下拉框之后，页面上没有任何地方能看出"现在到底筛了什么"，
  > 只能挨个把下拉框翻一遍；列表空了会以为是数据没了。
  > 只调了排序时，这条会写「排序」而不是「已筛选」——排序不是筛选。

**三种「不用手打」的筛法** —— 这一轮新增的重点，解决的是「想筛合适的工作，但每次都要把四个下拉框翻一遍」：

| 方式 | 在哪 | 怎么用 |
|---|---|---|
| **⚙ 一键按偏好筛选** | 筛选栏下面那行 | 点一下，按「**⚙ 我的求职偏好**」（同一行右边那块折叠面板）里的**目标城市 / 薪资底线 / 不能接受的点**筛；再点一下取消。按钮右边那行小字会写清「现在会按什么筛」 |
| **快捷筛选胶囊** | 筛选栏下面那行 | 5 个「一点就开、再点就关」的开关：🏆 高匹配 / 🆕 本周新 / 💰 薪资达标 / 📨 未投 / 🚫 排除不能接受的点。**可叠加**，叠加是「同时满足」，只会更少不会更多。每个胶囊右边带个小数字，是「点下去会剩几个」 |
| **自然语言搜索** | 关键词搜索框 | 直接敲「**杭州 运营 15k 不要外包**」，它自己拆成 城市 / 薪资 / 排除词 / 关键词 |
| **🤖 按简历推荐** | 右上角动作栏 | 用简历给一批岗位**批量打匹配分**，跑完自动按分排序 |

筛选栏右边的「重置」会把**偏好开关和快捷胶囊一起清掉** —— 不清的话用户以为重置了，列表却还是被偏好偷偷筛过的那批，只会更迷惑。

**「⚙ 我的求职偏好」—— 偏好设置搬进岗位库了**（这一轮从设置页挪过来的）

- **为什么搬**：偏好本来就是"用来筛岗位"的东西，那就该放在筛岗位的页面里。以前是「设置 → 改 → 回岗位库 → 再点筛选」，来回跳页。
- **长什么样**：筛选栏下面那行，左边是「**⚙ 按我的偏好筛选**」开关，右边是「**⚙ 我的求职偏好**」折叠面板。点头部标题就展开 / 收起。
- **改完即时生效，没有「保存」按钮** —— 这是刻意的。以前"改完记得点保存"踩过太多次：改了忘点、点了没生效、生效了却以为没生效。
  现在**每个字段一改立刻落盘**，面板头部那行摘要「当前生效：杭州 · 10K 以上 · 排除 外包」同步跟着变。
  连续打字时列表重画会**防抖约 0.4 秒**，所以**输入框不会掉焦点**。
- **面板里有**：期望岗位（和采集页共用同一个选择器）/ 目标城市 / 薪资底线 / 不能接受的点 / 期望薪资上限 /
  我的年限 / 我的最高学历 / 求职方向关键词 / 对口行业 / 「用内置画像词」/ 「进入岗位库时默认应用这些偏好」。
- **设置页那张「② 求职偏好」卡已经整卡删了**（第 23 轮）。它本来只是块指路牌（一句「已移到岗位库」+ 一个跳转按钮 + 一行当前生效），
  而入口在岗位库筛选栏上**本来就有** —— 两块重复导航反而容易让人以为"有两份偏好"。现在入口只有这一处。

> 缺字段的胶囊（💰 薪资达标 / 🚫 排除不能接受的点）点下去也是**就地展开这块面板**，不跳页 ——
> 跳页等于让用户自己跑到另一个页面里找刚才想填的那个字段。

> ⚠️ 有一类胶囊是「**未就绪**」状态（虚线、半透明）：💰 薪资达标 需要先填薪资底线、🚫 排除不能接受的点 需要先填不能接受的点。
> 没填的时候点它**不会假装生效**，也不会把你甩到别的页面去 —— 它会**就地展开「⚙ 我的求职偏好」那块面板**，
> 让你在同一个页面里把缺的字段补上。一个点了没反应的按钮比没有这个按钮更糟，跳页也只是让用户自己去找。

**「⚙ 一键按偏好筛选」的口径**（都是刻意的，别当成 bug）：

- **薪资为空的岗位一律保留**。采集回来的岗位常常没写薪资（BOSS 上显示「面议」），如果按「没写薪资就筛掉」处理，用户会以为岗位丢了。
- **福利没采到的岗位一律保留**。列表页的福利标签常有缺失，按「没写福利就是没有」筛，同样会让用户以为岗位丢了。真要看区别，卡片上会标「🎁 福利未采集」，不靠静默筛掉来表达。
- **「不能接受的点」只查标签 / 岗位名 / 公司名，不查 JD 正文**。因为「外包」「驻场」在 JD 里常出现在「本岗位**非**外包」「非驻场项目」这种反向表述里，扫正文会误杀。
- **偏好没填时按钮不禁用**，点了会**就地展开偏好面板**让你补 —— 禁用按钮等于死路，跳页等于让你自己找路。
- 偏好在库里**一条都匹配不上**时，空列表会给你三个出口：「⚙ 去调整偏好」/「取消偏好筛选」/「清空全部筛选」，不会把你困在空页面上。

**「⚙ 我的求职偏好」面板里，这一轮新加了两块**（都在同一面板内，就地展开、即时落盘，不跳页）：

- **🎁 期望福利（多选）**：五险一金 / 公积金 / 双休 / 年终奖 / 带薪年假 / 股票期权 / 定期体检 … 等 18 项，**可多选**，旁边一个「满足方式」开关：**全部满足（AND）** 还是 **任一满足（OR）**。
  - 勾「双休 + 年终奖」选"全部满足"，就只留两个都有的岗位；选"任一满足"，有双休或年终奖都算。
  - 口径同上：**福利没采到的岗位不筛掉**（标「福利未采集」，不静默丢）。
- **📍 期望地点（城市 > 区 > 商圈 三级）**：先选城市，再下钻到区，再下钻到商圈。
  - 区给了**内置候选**（只覆盖杭州/上海/北京/深圳/广州，只当候选、不是全部）；商圈**不内置**，只认库里真实采到过的，也能自己手输。
  - 地铁站：BOSS 页面本身不直接给「地铁」字段，所以**地铁当"商圈/地标"一起处理** —— 采到哪个商圈，就能按哪个商圈筛。
  - 口径：**没采到区/商圈的岗位不筛掉**，但卡片上会标「📍 区未知」，计数行会写「其中 N 个没采到区/商圈，先留着」。

**🎯 本地「合适度」—— 零成本、可解释，不花 token**

库里的岗位会**自动**被算一个 0-100 的「合适度」，分 A/B/C/D 四档，并且**说得出为什么**。
它和右上角「🤖 按简历推荐」的 **AI 匹配分是两回事**：那个要联网、要花 token、读的是 JD 语义；
这个纯本地、结果可复现、每条都能摊开讲清楚。两者在界面上分开显示，别混着看。

| 在哪 | 看到什么 |
|---|---|
| 顶部 | 「🎯 合适度」分级条：`A 强推 N` `B 可投 N` `C 观望 N` `D 跳过 N` + `剔除 N`。**点一下就是筛选，再点一下取消** |
| 每张卡 | 一个分级徽标 + 五维小标签 + **一行「为什么」**（见下） |
| 紧凑列表 | 「合适度」这一列同样带徽标 + 原因行，不用展开也能看明白 |
| 点开详情 | 最上面一整块拆解：分数圆环 + 五条维度进度条 + 命中的关键词 + 加减分明细 + 降级提醒 |
| 筛选栏 | 「合适度不限 / A / B / C / D」下拉；排序里有「合适度由高到低（被剔除的一律沉底）」 |
| 怎么算的 | 分级条右边点「怎么算的」→ 弹出完整口径，含**当前到底用的哪几个关键词** |

**「每一条都标明原因」—— 这是这块的核心，不是装饰。**

- 卡片上那行「为什么」**正反两面都说**：先说命中了什么（岗位名就是运营方向 / 关键词命中了"短视频、直播" / 薪资起点就达到期望 / 经验要求正好对上 / 福利扎实 …），
  再用 `⚠` 带出短板（薪资上限比期望低一点 / 经验要求差得比较多 / 福利只看到软福利，没写双休或五险一金 …）。
- **被剔除的岗位也写原因**，而且用醒目的红字 —— 因为「为什么没推它」和「为什么推它」一样重要。
  卡片上出现的是 `🚫 城市不符：岗位在"北京"，你的目标城市没有它`，而不是一个让人摸不着头脑的 `0 分`。
- 详情页里还会把原因**和五维得分、命中的关键词对起来**，所以"这分是怎么来的"永远点得出来。

> 为什么强调这件事：只报一个分数、不写理由，等于让用户自己猜；**只说好话的原因行更糟** ——
> 它会把 C 级岗位包装得看起来像 A 级。所以原因行里**必须有 `⚠`**，没有短板也要写清"哪一项是按中性算的"。

**五维（合计 100）**：岗位方向 30 · 关键词命中 30 · 薪资匹配 20 · 经验匹配 10 · 福利稳定 10
**动态加减分**：HR 今日活跃 +4 / 3 日内 +2 / 长期不活跃 -3 · 标「急招」+3 · 行业对口 +3 ·
学历门槛高于你 -3 或 -6 · 代招 -3 · 信息残缺 -3
**分级**：A ≥80 强推 · B 60-79 可投 · C 40-59 观望 · D <40 跳过

> **「被剔除」和「分低」是两回事，别混。**
> 城市不符 / 岗位名是「销售、客服、行政」这类蹭「运营」词的 / 命中你写的「不能接受的点」→
> **直接剔除、根本不给分**，卡片上写的是**原因**而不是一个 0 分。
> 所以列表里会出现「3 条 A/B/C 级 + 2 条被剔除」，而不是「2 条 0 分」。

> 三条刻意的口径（不是 bug）：
> ① **「面议」不额外扣分** —— 薪资维度里它按中性算，不能一边说中性一边又扣；
> ② **「蹭词」只在岗位名上判，不扫 JD** —— JD 里「配合销售」「对接客服」太常见，扫正文会大面积误杀；
> ③ **下午茶 / 零食这类软福利不计分**，否则「只有下午茶」会和「只有双休」拿同样的分。
> ④ **大小周 / 单休也不算福利** —— 那是妥协不是福利，只有**双休**才进福利档位（详见对比页的「假期 / 休息」）。

口径在「**岗位库 → ⚙ 我的求职偏好 → 🎯 本地合适度打分口径**」里改：期望薪资上限 / 我的年限 / 我的最高学历 /
求职方向关键词 / 对口行业。关键词**留空就用内置的 23 个画像词兜底**（点「用内置画像词」就是清空它）。

**自然语言搜索认这些写法**：

| 你敲 | 会被理解成 |
|---|---|
| `杭州` `上海` | 城市。岗位地点**包含**该词就算命中，所以「杭州」也能命中「杭州·西湖区」 |
| `15k` / `15k-20k` / `10k以上` / `1.5w` / `1.5万` | 薪资（`1.5万` = 15K） |
| `不要外包` / `排除外包` / `不接受劳务派遣` | 排除词 |
| 其余的词 | 关键词，**多个词是「都要命中」**（搜「运营 短视频」= 标题/JD 里同时有这两个词） |

搜索框下面会出现一行小字，告诉你**它理解成了什么**（「理解为：城市=杭州 · 薪资≥15K · 关键词=运营」）。
理解错了就点小字右边的「**当普通关键词搜**」，退回「拿整串文字去匹配」的老口径。

> 为什么多关键词要改成「都要命中」：原来的搜索是拿整串匹配子串，搜「运营 短视频」要求 JD 里**连续出现这 6 个字**，
> 几乎永远搜不到 —— 用户会以为库里根本没这类岗位。注意退回老口径后，「杭州 运营 15k」这种整串一样可能一条都搜不到，
> 这是**预期行为**（老口径就是这么窄），所以小字里那个退路是给「解析错了」用的，不是给日常搜索用的。

**「🤖 按简历推荐」怎么跑**：

1. 点右上角那个按钮 → 选范围（全库 / 当前筛选结果 / 只选还没投的）→ 选简历 → 开始
2. 一个岗位一个岗位**串行**跑（不是并发轰炸），每 10 个停一下，避免撞服务商限流
3. 单个失败会**自动重试 1 次**；连续 3 个失败会停下来问你「继续 / 停」
4. 随时能取消，**已经评到的分会保留**
5. 跑完自动按匹配分排序。这些分会被「🏆 高匹配」胶囊和「待跟进」页的「高匹配还没投」直接用上
6. 已经有分的岗位默认跳过（想重跑就勾「重新评分」）

> 没配模型时点它不会静默：会给一条带「去配置」的提示。

**三种视图**（筛选栏右侧按钮，切了会记住）：

| 视图 | 适合 |
|---|---|
| ▦ 卡片 | 信息最全，逐个看 |
| ☰ 紧凑列表 | 一屏看更多，适合批量扫 |
| 🏢 按公司 | 同一家公司的岗位归到一个折叠块，summary 直接给「N 个岗位 / N 个没投 / 最远：状态」 |

**列表**：岗位卡片，点开进详情
- 卡片上的 JD 默认只显示 **120 字摘要**，要读全文点卡片里的「展开全文 ▾」（长 JD 才不会把列表撑得没法扫）
- 鼠标移到卡片上，右下角会浮现一个 📦（归档 / 取消归档）—— 归档不用再点进详情

**批量操作** —— 列表右上角「☑ 批量操作」：
- 点卡片就是勾选（不会打开详情），底部浮出一条操作栏（跟着列表滚，不会跑丢）
- 支持：全选本页 / 反选 / 清空 / 收藏 / 归档 / 打标签 / 加入看板 / 删除 / 退出批量
- 「加入看板」会先让你选一个状态，再批量建/推进投递记录
- 批量删除同样可以整体撤销

**删除都能撤销** —— 单个删除和批量删除都不再弹确认框，改成**直接删 + 右下角弹一个带「撤销」的提示**（10 秒内点一下就整包回来，鼠标停在上面倒计时暂停）。
> 为什么改：确认框每次都要多点一次，而撤销只在真出事时用。
> 删岗位会**连带**它的投递与面试记录（不然看板上会留下指向空岗位的孤儿卡），撤销时也是一起回来。

**标签管理** —— 筛选栏标签行最右「⚙ 管理标签」：看每个标签被几个岗位用了、改名（自动合并同名，不会产生重复）、删除（从所有岗位上摘掉，岗位本身不动）、只看这些。

**详情弹窗**（顶部粘性操作区 + 左侧折叠分组）：
- 顶部**粘住不滚**：岗位名 / 薪资 / 收藏 / 归档 / 当前状态（或「＋加入看板」）/ 5 个 AI 动作
- 左侧六个折叠分组：① 结构化信息（默认展开）② AI 分析结果 ③ 原始 JD ④ 标签 ⑤ 我的笔记 ⑥ 模拟面试记录
- AI 动作里多了 **🎤 模拟面试**（见第 4 节末）
- 底部固定栏：「⋯ 更多」菜单 + 关闭。低频和危险操作（编辑字段 / 复制岗位信息 / 加入对比 / 导出 Markdown / **删除**）都收在「⋯ 更多」里
  > 为什么挪：删除以前排在弹窗最底部，删个岗位得滚半天，还容易顺手点到。

**六个折叠分组里有什么**：

| 分组 | 内容 |
|---|---|
| ① 结构化信息 | 公司 / 行业 / 地点 / 远程 / 薪资 / 年终奖 / 福利 / 职责 / 硬性要求 / 风险标记 |
| ② AI 分析结果 | 匹配度、优劣势、风险点、建议（跑过 AI 才有） |
| ③ 原始 JD | 粘贴进来的原文，一字不改 |
| ④ 标签 | 打标 / 摘标 |
| ⑤ 我的笔记 | 随手记，跟着岗位走 |
| ⑥ 模拟面试记录 | 每轮得分、逐题点评（做过模拟面试才有） |

除这六组外，弹窗里还能看到这个岗位的**投递记录 + 进展时间线**（投过没有、走到哪一步）、**绑定的简历版本与匹配结论**、**相关面试**。

**BOSS 采回来的岗位，详情里还能看到这些**（这些字段以前采回来却在导入时被丢掉了，2026-09-30 补上）：

| 字段 | 从哪来 | 有什么用 |
|---|---|---|
| **代招** | BOSS 详情接口的权威字段 | 标注「代招」的岗位，劳动合同多半不在这家公司。岗位卡和详情页都会挂橙色徽标 |
| **已失效** | 同上 | BOSS 已下线的岗位，挂红色徽标 —— 投了大概率没回应 |
| **详细地址** | 详情接口 | 「杭州滨江区智汇中心A座3楼」这种门牌级地址，比只到「杭州」有用得多（判断通勤） |
| **公司规模** | 详情接口 | 20-99 人 / 100-499 人… |
| **公司简介** | 详情接口 | 判断公司靠不靠谱、是不是皮包公司的主要线索 |
| **HR 职位 / 是否在线** | 详情接口 | 「人力资源总监（在线）」回你消息的概率，明显高于「HR 实习生」 |

> **「代招」尤其值得看**：以前想筛掉外包，只能去 JD 正文里猜「外包」两个字 ——
> 而 JD 里「本岗位**非**外包」这种反向表述会把人误伤。现在有了 BOSS 的权威字段，
> 偏好里写「排除外包」就能**精准命中**真正的代招岗位，也不会误杀。

> **「技能标签」不再叫「硬性技能」了**：BOSS 的「技能标签」列，实际内容多是
> 「接受无经验牛人」「不接受居家办公」这类**招聘卖点**，不是录用门槛。
> 以前它被当成「硬性技能」喂给 AI，会系统性地把匹配分压低；现在统一叫**招聘标签**，
> 并明确告诉模型「这不是硬要求」—— 真正的技能要求从 JD 正文里读。

**改了没保存会被拦一下** —— 岗位字段、投递记录、面试记录、简历这几个表单，改完直接点 ✕ / 取消 / 按 Esc / 点遮罩，会问一句「有修改还没保存，确定放弃吗？」。
（点「保存」不会被问 —— 保存走的是另一条路。）

**其他入口**：
- 「📥 从爬虫结果导入」→ 导入本地 `boss-crawler` 跑出来的 `qualified_jobs.json` / `scored_jobs.json` / `postdata/*.csv`
- 「✎ 手动新增」
- 「⤓」→ 导出岗位库 CSV

### 2. 📡 采集岗位（可选，批量捞岗位）

岗位多的时候，一条条复制粘贴太累。这一页可以**一次把几十上百个岗位捞回来**。

**怎么用**：回工作台文件夹，**双击 `启动采集器.cmd`**。会弹出一个黑窗口（别关它）+ 自动打开浏览器。然后：

1. 点 **「🔑 ① 登录 BOSS」** → 弹出真实 Edge 窗口 → 你在里面**扫码登录**
2. 填采集参数（关键词 / 城市 / 薪资 / 条数）
3. 点 **「📡 ② 开始采集」** → 下面日志窗实时滚动，**「采集器状态」卡的「当前任务」会显示进度条 + 已用时**（采集没有精确总进度，进度条是滚动动画 + 计时，让你知道它还在跑、跑了多久）
4. 跑完会**弹一个醒目的完成提示**（带总耗时）+ 提示音，然后点 **「📥 导入岗位库」** → 采集到的岗位就进岗位库了，接着做 AI 匹配、投递跟踪

**⏱ 开跑前先告诉你「大概要等多久」**：参数卡里填好城市和期望后，「开始采集」旁边会出现一行预估，例如
「预计约 5.2 分钟（列表 1 分 + 详情 4.2 分），详情只抓最合适的 50 个」。
改城市 / 期望 / 条数，这行会跟着变 —— 不用点下去才猜要等 3 分钟还是半小时。

> **为什么详情只有 50 个**：详情要一个个岗位点进去读，是整条链最慢、也最容易触发 BOSS 风控的一步（官方风控阈值大约 200 个）。
> 所以按**本地合适度排序，只抓最合适的 50 个**详情，其余岗位保留列表页字段（标题/公司/薪资/城市）——
> 这些字段足够做初筛，真正需要 JD 全文时才值得再花那一次请求。这个上限在 `采集器/server.py` 的 `_EST_DETAIL_TOP_N`，
> 与 `boss-crawler` 的 `DETAIL_TOP_N` 保持一致（有测试守着两处别漂移）。

**🗂 想看以前采过哪几批**：参数卡下面「运行目录」那一行有 **「查看采集历史 →」**，点开会列出**历次采集的目录**，
标明哪一轮是「当前」、哪些「已归档」（点「清空结果」是把文件**归档**、不是删除，所以历史都在），
每一轮都能**一键复制路径**去文件管理器里翻。以前只能看到 LATEST 那一个目录，想找 9-30 那批数据得自己去翻文件系统。

**🆕 只看本次新增**：结果区筛选栏有一个「**本次新增 N**」开关。因为结果池是**跨轮累积**的（同一个关键词跑两次，
第二次的池子里有第一次采到的），想只看**这一轮真正新捞到的**就把它打开 —— 计数行会如实写「结果池共 N 个 · 本次新增 M 个」，
不再把跨轮累积说成「本批」。切到「只看新增」后，导入按钮也会跟着只导新增的那几条。

**🎯 岗位期望：不用自己想关键词，从 1200+ 个岗位里挑**

不知道关键词该写什么？点参数卡里的 **「➕ 选择岗位」**。选择器里有**两份数据**：

| | 是什么 | 规模 |
|---|---|---|
| **① BOSS 官方岗位分类树** | 官方标准叫法，按「大类 → 子类组 → 岗位」三层组织，例如「互联网/AI → 后端开发 → Java」 | 28 大类 / 161 子类组 / **1098 个岗位** |
| **② 🔥 真实在招岗位** | **招聘方实际写出来的岗位标题**，按岗位分类分组，每个名字后面那个小数字是「采集样本里出现过几次」 | 杭州 · 运营方向 **300 条采集样本 / 176 个岗位名** |

② 是这份数据最有意思的地方 —— 官方树里没有「抖音短视频运营」「天猫/淘宝运营店长」「自媒体内容运营」这种写法，但它们才是你真正要在 BOSS 上搜到的东西。**用②当关键词去采集，命中率通常比官方标准名更高。**

怎么用：

- 顶部**搜索框**直接搜，**两份数据一起搜** —— 输「运营」既出官方的「新媒体运营」，也出真实在招的「抖音短视频运营」（后者带一个「真实在招」小标签）
- 也可以**折叠浏览**：官方树按大类展开；「🔥 真实在招岗位」块在最上面，按分类展开
- 真实在招的每个分组都有 **「＋ 本组全加（N）」/「－ 本组全去」** —— 想一次把「内容运营」这一类的岗位全丢进去搜，点一下就行
- 选中的岗位会以标签列在「已选」区，点 ✕ 去掉，或点「清空」
- 两份数据都没有的岗位，搜索框输完点 **「就用「xxx」作为岗位」** 也能加进来

点「确定」后，这些岗位会**自动并入搜索关键词**一起去采集。所以：

- 可以**只选岗位、不填关键词** —— 不用自己想词了
- 也可以**岗位 + 手动关键词混着用**，重复的自动去重

岗位库的「**⚙ 我的求职偏好**」面板里有一个**同样的「期望岗位」**（同一个选择器）。填了之后，岗位库的 **「⚙ 按我的偏好筛选」** 会只留下岗位名命中这些岗位的岗位 —— 等于「我只看这几类岗位」。**改完即时生效**。

**「④ 采集结果」可以像 BOSS 里那样筛** —— 捞回来几十上百个岗位后，不用一股脑全导进去再回头筛。结果卡上有一排筛选栏：

- **关键词搜索**：支持「杭州 运营 15k」这种自然语言（城市 / 薪资 / 排除词 / 关键词自动拆解），和岗位库搜索一个口径
- **岗位名下拉**：★ 选项就来自上表 ② —— **176 个真实在招岗位名**，按分类分成 10 组，名字后面的括号是采集样本里的出现次数。选「内容运营」会把「内容运营主管」「新媒体内容运营」这些一起留下（双向包含，不会因为标题更长就漏掉）
- **城市 / 行业下拉**：自动从这批采集结果里枚举出来，选哪个筛哪个
- **📍 区 / 商圈（多选）**：★ 这一轮新增，比城市更细一层 —— 区、商圈各一排多选胶囊。
  **选项只来自这批结果真实采到的**（不会把内置行政区划里没采到的「上城区」塞进去，免得点了显示 0 条）；
  **换城市会自动清掉旧区/商圈**（杭州的「滨江区」拿到上海就不成立了）。
  同样，**没采到区/商圈的岗位不筛掉**，但卡片标「📍 区未知」、计数行写「其中 N 个没采到区/商圈，先留着」
- **薪资档位**：10K 以下 / 10-20K / … / 未标薪资
- **已评分 / 未评分**：只看到底谁还没让简历打过分
- **合适度**：A/B/C/D 分级筛选 + 一条分级条（`A 强推 N` … + `剔除 N`，点胶囊就是筛）。
  跟岗位库**同一份打分口径**，捞回来当场就能看出这批成色，不用先导进去再回头筛
- **排序**：原始顺序 / 薪资高→低 / 合适度高→低 / 匹配分高→低 / 按公司

筛完之后，导入按钮会变成「**📥 导入筛选后的岗位（N）**」，旁边还留了个「导入全部」——想精准导一批就筛，想全要就点另一个，互不干扰。筛选只影响这一页的展示，不写库、不动采集器。

**导完一键清掉结果区**：把岗位导进岗位库后，结果区那几百条还挂着容易误点重复导入。点「**🗑 清空结果**」会把采集器侧的结果文件**归档**到 `results-archive/`（不是删除，误清能整批找回），结果区当场清空；**岗位库完全不受影响** —— 已导入的数据在你浏览器里，跟这些文件无关。

**没启动采集器会怎样**：这一页会显示引导卡，告诉你双击哪个文件就行。其它所有功能**完全不受影响** —— 粘贴导入、AI 解析、投递看板都能正常用。

**采集参数的取值建议**：

- **关键词**：3-6 个精准词最好。别把「运营」这种大词和「新媒体运营」混着放，大词会把一堆不相关的岗位捞进来。
- **条数**：第一次建议 20-30 条试试水。条数越多越慢。
- **薪资 / 城市**：透传给 BOSS 的搜索条件，等于你在网站上手动筛了一遍。

**采集参数会自动体检**：填的采集条件和「**⚙ 我的求职偏好**」里的偏好如果不打架，就什么都不显示；一旦对不上，参数卡下面会弹一条黄条提醒，并给一键修正。目前盯两种情况：

- **期望薪资落不进采集档位**：比如偏好里写了期望薪资，采集档位却选了不覆盖它的那一档 —— BOSS 会在**服务端**先把正好匹配的岗位筛掉，你采回来的全是「薪资更高、要求也更高」的。黄条会告诉你该改哪一档，点一下就改。
- **采集城市和目标城市对不上**：偏好里是「杭州」，采集填了「上海」—— 采回来的城市基本不是你要的。
- **期望地点选的区/商圈不属于采集城市**：参数卡里填的「📍 期望地点」下钻到了杭州的「滨江区」，采集城市却选了「上海」—— 白采一轮才发现筛成空。黄条会提醒你区跟城市对不上。

> 为什么加它：真正的「投了白投」往往不是简历不行，而是**源头就把合适的岗位筛掉了**，
> 然后你以为「采回来的都不匹配」。

**两条注意事项**：

- 采集期间**别关那个 Edge 窗口**，也别在里面手动乱点
- **频率别太猛**。一次几十条、别连着跑十几轮 —— 这不是技术限制，是保护你自己账号不被风控限流

> 数据是**跟着模式走**的：直接双击 `index.html`（`file://`）和通过采集器打开（`http://127.0.0.1:8738`）是两个不同的浏览器来源，localStorage 不互通。建议固定用一种。已经在一边录了数据、想在另一边用，就「设置 → 导出 JSON」再「导入」。

**导入完可以直接接着评分** —— 采集回来的一批岗位导进库之后，右下角的提示会多一个「**🤖 现在就评分**」按钮，点它就用你简历给这批新岗位打匹配分，不用自己跑去岗位库找入口。
还没导入的采集结果，列表上方会提示「N 个采集来的岗位还没评分」，同样给你一个入口。

> 为什么加它：采集 → 导入 → 评分 本来是三个页面来回跳，很容易导完就忘了还有"评分"这一步，最后库里躺着一堆没分的岗位，「高匹配」筛选也就一直是空的。

#### 上传 PDF / Word 简历（不用再复制粘贴）

页头「📄 上传简历文件」、空态里的「📄 上传 PDF / Word」、简历表单里的
「📄 上传 PDF / Word 自动转文字」—— 三个入口一个意思：**选一个文件，自动转成文字存进来**。

| 你选的文件 | 怎么读 | 需要开着采集器吗 |
|---|---|---|
| `.txt` / `.md` / `.markdown` | 浏览器本地直接读 | **不需要**（离线可用） |
| `.pdf` / `.docx` | 交给本机**采集器**抽文字 | **需要**（先跑「启动采集器.cmd」） |
| `.doc`（旧版二进制） | **读不了** —— 用 Word 打开「另存为 .docx」再上传 | — |
| 扫描件 / 图片版 PDF | 抽不出文字（里面是图，不是字） | 需要 OCR，请改用手打或可选中文字的 PDF |

几点说明：

- **PDF / Word 的抽取不花你的模型额度、也不需要配 API Key** —— 它只把文字抽出来，
  不发给大模型、不起解析任务、不占采集任务队列。（「📄 上传简历并解析」才是会调模型的那个。）
- 抽取用的是 `PyPDF2` + `python-docx`，跟你点「上传简历并解析」用的是**同一个解析器**。
- 单个文件上限 **20MB**。
- 抽不出文字时会明确告诉你原因（多半是扫描件），不会假装成功塞一段空文字进去。

**导出成能直接发出去的文档**：简历卡片上点「⤓ 导出 PDF / Word」，弹出导出面板：

- 左边是**实时预览**（A4 版式，白底黑字，不跟页面主题走 —— 不然深色主题下导出个黑底简历就废了）
- 三种排版主题：

  | 主题 | 长什么样 |
  |---|---|
  | 极简 | 黑白，没有花哨装饰，最通用 |
  | 稳重 | 深蓝主色，正式投递用 |
  | 紧凑 | 字号行距压紧，内容多时用 |

- 上面会提示**哪些字段是空的**（比如没填手机号），提醒你补完再导
- 四个出口：

  | 按钮 | 干什么 |
  |---|---|
  | 导出 PDF | 开一个打印窗口，在打印对话框里把「目标打印机」选成「**另存为 PDF**」 |
  | 导出 Word | 下载一个 `.doc`，Word / WPS 打开能直接改，也能再另存为 PDF |
  | 导出 Markdown | 纯文本，方便贴进飞书 / Notion / Obsidian，或丢给 AI 改 |
  | 导出 HTML | 存成一个自包含的 HTML，双击打开就能看，也能 `Ctrl+P` 存 PDF |

> **为什么 PDF 走「打印」而不是直接生成**：真正生成 PDF 要引几十 MB 的字体与排版库，跟本工具「零依赖、双击即用」的原则冲突。
> 浏览器的打印对话框里本来就有「另存为 PDF」，效果一样，还顺带能选纸张和边距。
> 走打印这条路，简历里的**中文字体也不会缺字** —— 用的是你系统里的字体。

页面结构（从上到下）：

1. **顶部免责**：明确写「仅供参考，不构成法律意见」「重大决策以官方公示为准」—— 这个工具帮你**快速看个成色**，不是给你下法律结论。
2. **四张统计卡**：红灯 / 黄灯 / 绿灯 / 未评定 各几家。**「未评定」单独一张卡**，就是让你看到「还有多少家根本没查过」—— 没查 ≠ 没问题。
3. **范围切换**：全部公司 / 待投递 + 收藏 / 仅合适度 A、B 级 —— 默认查「准备投的那批」。
4. **搜索 + 灯位筛选** + 公司清单，每家一行：
   - 灯（🟢 绿灯 / 🟡 黄灯 / 🔴 红灯 / ⚪ 未评定）+ 公司名 + 判定理由
   - 工商行（成立时间 / 注册资本 / 实缴 / 经营状态）+ 风险行（被执行 / 失信 / 开庭 / 异常 / 处罚 / 劳动纠纷）
   - ⛔ **组合预警条**：实缴 0 + 成立不足 1 年 + "底薪加提成"话术 + 一堆劳动仲裁，**凑够 3 项**才会亮「慎入」红条
5. **背调配置**：路线 B（接天眼查 / 企查查开放平台 API）的 Key 配置位 —— 不配也能用，配了才自动拉工商照面和司法风险。

**怎么查（路线 A，0 成本）**：

- 点公司名 → 弹窗里给三个按钮，一键跳 **天眼查** / **爱企查** / **国家企业信用信息公示系统**（gsxt）。
- 前两个能直接带公司名搜；**gsxt 是官方站、用 POST 检索，做不成带公司名的深链**，所以它只跳首页、让你自己搜 —— 这是照实说明，不是偷懒。
- 查完可以**手工录入**结果（工商 5 项 + 风险 6 项 + 招聘话术 + 备注），录入时**边填边实时预览**会判成什么灯。

**判灯口径**（照实说，不吓唬人也不包庇）：

| 灯 | 判据 |
|---|---|
| 🟢 绿灯 | 成立 2 年以上 + 无被执行/失信 + 劳动纠纷少 |
| 🟡 黄灯 | 成立 <1 年 / 实缴为 0 / 少量经营异常 / 有开庭公告 |
| 🔴 红灯 | 被执行 / 失信 / 大量劳动仲裁 / 行政处罚频繁 / **经营状态「注销/吊销」** |
| ⚪ 未评定 | **还没查 / 数据不全** —— 绝不默认成绿灯 |

几个刻意的口径（别当 bug）：

- **「实缴为 0」和「实缴没填」是两回事** —— 没填是"不知道"，不会按「实缴 0」报警；只有真查到是 0 才进黄灯。
- **没数据就是「未评定」，绝不默认绿灯** —— 把"没查"显示成"没问题"是最危险的错。
- **组合预警收紧为 ≥3 项才「慎入」** —— 实缴 0 在初创公司太常见，单条就喊"慎入"会让人学会无视整个提示。
- **岗位卡片上也挂灯**（公司名旁边），但**只在真查过时挂** —— 几百张卡全挂同一个灰点纯噪音；要看你查了谁、谁没查，来背调页看「未评定」卡。

> ⚠️ 成本与边界：接 API 后约 0.5~1.3 元/家，同一家公司的结果**本地缓存、不重复查询**；API Key **只存本地**，导出备份时会**自动抹掉 Key**（备份常被扔网盘 / 发人）。

## 四、数据在哪 · 怎么备份

| 问题 | 答案 |
|---|---|
| 数据存在哪 | 浏览器的 localStorage，键名 `jobhunter.db.v1.<账号>`（按账号分） |
| 会上传吗 | **不会**。没有任何后端 |
| 换电脑怎么办 | 设置 → 「⤓ 导出 JSON 备份」→ 新电脑「📥 导入 JSON」 |
| 导入会覆盖吗 | 可选**合并**（保留本地多出来的）或**覆盖** |
| 清浏览器数据会丢吗 | **会**。所以定期导 JSON 备份 |
| 忘了备份咋办 | 有 `jobhunter.db.v1.<账号>.bak` 兜底，但别指望它 |
| 采集的数据在哪 | 岗位落在 `~/.workbuddy/skills/boss-crawler/assets/<时间戳>/`；上传的简历存在 `采集器/data/resume/` |
| 采集器日志 | `采集器/data/server.log`（服务自己的日志；采集输出在网页上实时看） |

**多标签页**同时开着编辑时，会检测到冲突并提示重新载入，防止互相覆盖。

### 本机多账号（数据沙箱）

侧边栏底部有个账号区。你可以建多个账号，**每个账号一份完全独立的数据**：

| 操作 | 怎么用 | 效果 |
|---|---|---|
| 新建账号 | 点「切换」→ 输个新名字 → 切换 | 新账号从零开始（岗位/投递/偏好都是空的），自动创建 |
| 切换账号 | 点「切换」或直接点别的账号名 | 整页重载，看到的是那个账号的数据 |
| 换回原账号 | 再切回原名字 | **数据完整恢复**（从来没被覆盖，只是换了目录看） |
| 登出 | 点「登出」 | 回到 `default` 账号 |

要点：

- **这是数据沙箱切换，不是网络登录**。数据还在你本机浏览器里，账号只是把数据分成了几份，彼此隔离、互不覆盖。
- **密码可选、仅防误操作**：设了密码的账号，切换时要输对才能切进去。密码**不加密、不联网**，本地文件本就可读，所以别拿它当安全保护。
- **`default` 是兜底账号**，删不掉；你以前的数据（升级前那份）会自动归到 `default`。
- 换了账号，采集器那边是**共享同一个 BOSS 登录态**的（采集器不感知账号），所以换账号不用重新扫码登录 BOSS。

**你可能会忘记备份，所以它会主动提醒你**：打开工作台几秒后，如果你有一阵子没导出过 JSON，右下角会弹一条提示，上面带一个「去导出」按钮，点一下跳到设置页。三条口径：

- **空库不提醒** —— 一条数据都没有的时候不烦你
- **第一次用没有「上次导出时间」**，就拿你**最早一条记录是哪天建的**当基准 —— 也就是说你用了 10 天没备份，它就会提醒你
- **提醒过就消停一阵** —— 不会每次打开都弹（默认隔 7 天）

想改间隔或干脆关掉：**设置 → ⑥ 数据与备份 → 「定期提醒我导出备份」**，旁边可以选每隔 3 / 7 / 14 / 30 天，取消勾选就彻底不提醒了。这一页还会写清你「上次导出是几天前」。

> 为什么在意这件事：数据只在你这个浏览器里，清一次缓存就没了，而且**没有任何云端可以找回**。提醒的成本很低，丢数据的成本很高。

## 五、边界与风险（照实说）

### 这个工具做什么

| | |
|---|---|
| **登录** | 弹出**真实 Edge 窗口**，你自己扫码。不代填账号密码，不保存你的登录凭证。 |
| **读取** | 打开列表页与详情页，**调用页面自身的数据接口**读取岗位信息（即浏览器加载页面时本来就会请求的那两个接口）。**这比手动翻页更密集，更容易触发站点风控**——见下方「采集的取舍」。 |
| **结果** | 岗位清单交给工作台，后续解析 / 匹配 / 跟踪全在你本机完成。 |

### 刻意不做的事

- ❌ 不自动发消息
- ❌ **不自动投递**
- ❌ 不代填账号密码、不保存登录凭证

**为什么不做自动投递**：BOSS 无公开投递 API。机械化投递会被风控降权，连你**手动**投递都跟着受牵连。而且消息一发出去就撤不回来 —— 这是整条链上唯一不可撤销的一步，不该由脚本替你做。投递永远是你自己在 BOSS 里点。

### 采集的取舍

- **本质**：自动化地翻岗位列表与详情，**通过页面自身的数据接口读取**（浏览器加载页面时本来就会请求的接口）。比手动翻页快得多，请求密度也高得多。
- **风险**：接口级读取**比手动浏览更容易触发站点风控**。工具已做限速、随机抖动、分批冷却，并可按合适度封顶详情抓取数量来降低强度，但**不能保证不触发**。控制频率、别长时间连续跑，是保护你自己账号的实用建议。
- **数据**：全留本机。采集结果落在本地文件，工作台数据在你浏览器里，**不上传任何服务器**。

### 关于字段缺失

BOSS 详情页有安全验证，免登录链路通常**拿不到薪资和完整 JD**。工作台遇到缺失字段会如实标「面议」「需在 BOSS 内查看」，**不编造**。

### 跟 `boss-crawler` 的关系

工作台的采集功能**不是自己写的爬虫** —— 它只是调起你本机已装的 `boss-crawler` 技能，把命令行操作包成了界面。所以：

- 想用命令行 / 跑定时任务，直接用 `boss-crawler` 本身
- 采集的账号风险与频率控制，由你自己判断和承担
- 不想用采集器也完全可以：「📥 从文件导入」手动导它的历史产物（`qualified_jobs.json` / `postdata/*.csv`）

## 六、常见问题

**Q：岗位库顶部提示「还没配置模型接口」，但我看「📡 采集岗位」那页写着「模型配置 ✔ 已配 Key」，是不是坏了？**
不是。**这是两套互不影响的配置**：

| | 存在哪 | 管什么 |
|---|---|---|
| 采集器端 | `boss-crawler` 的本地配置文件 | 采集脚本自己要不要用模型 |
| 工作台端 | 你这个浏览器的 localStorage | AI 解析、匹配打分、话术、面试题 |

工作台要用的那套在 **设置 → ① 大模型接口** 里填。另外，那个黄色提示条右上角有个 ✕，点掉之后本次会话内所有页面都不再出现。

**Q：点了「确认」「删除」却没反应？**
这是 2026-09-25 修掉的一个系统性 bug（弹窗关闭回调抢答，导致点确认等于点取消），现在已修复。
如果你手上是一份旧副本，请用最新版覆盖。同类症状的排查手法：`F12` 看 Console 有没有 `ReferenceError`。

**Q：AI 按钮点了，弹窗一直停在「正在调用…」？**
现在不会了 —— 未配置 Key 会直接在弹窗里显示原因，并给一个「去设置页填 API Key」的按钮。
如果你看到它卡住，说明是旧版本。

**Q：弹窗关不掉 / 切页面后弹窗还浮在上面？**
现在切页面会自动收掉所有弹窗。同样，旧版本才有这个问题。

**Q：为什么老是弹「该备份了」？我不想看。**
它是按「你多久没导出 JSON」来判断的，默认超过 7 天提醒一次，**同一周期内只提一次**。
嫌烦就 **设置 → ⑥ 数据与备份 → 取消「定期提醒我导出备份」**，从此不再弹。
（或者把间隔改成 30 天，只当个季度提醒。）

> 提醒本身是有用的：数据只在你这个浏览器里，清缓存就没了，**没有任何云端能找回**。但要不要被提醒，你说了算。

**Q：打开是白屏 / 页面报错？**
按 `F12` 看 Console。多半是某个 js 没加载——确认 `js/` 和 `css/` 文件夹跟 `index.html` 在一起。

**Q：AI 按钮点了报错？**
1. 检查设置页 Key 填了没、点没点「测试连通」
2. 401 → Key 错；402 → 余额不足；404 → 模型名或地址错；429 → 太频繁
3. 用 Ollama 的话，确认本地服务起来了（`ollama serve`）

**Q：AI 返回的 JSON 解析失败？**
程序会自动让模型「修一次 JSON」再试。还失败就换个模型（小模型的 JSON 稳定性差一些）。

**Q：粘贴的中文乱码？**
CSV 导出带了 BOM，Excel 打开不会乱码。如果是从别处导入乱码，换 UTF-8 编码重新导出。

**Q：能手机上用吗？**
有基础响应式，窄屏侧栏会收起（左上 ☰ 展开）。但这是电脑端优先的工具，手机上体验一般。

**Q：薪资怎么显示「面议」？**
见第五节——免登录拿不到薪资时如实标注，不编。

**Q：点了「⚙ 按我的偏好筛选」，有些岗位没写薪资却留下来了，是漏网了吗？**
不是漏网，是**故意的**。采集回来的岗位常常没有薪资（BOSS 上显示「面议」），
如果按「没写薪资就筛掉」处理，用户会以为岗位丢了。所以规则是：**薪资字段为空的岗位一律保留**。
想只看到明确写了对得起底线的岗位，用「💰 薪资达标」那个胶囊也一样是这条口径 —— 要更严只能靠自己加标签筛。

**Q：为什么「不能接受的点」写了「外包」，「本岗位非外包」的岗位还是被筛掉了？**
正常情况下**不会被筛掉** —— 这个筛选项只查**标签 / 岗位名 / 公司名**，不看 JD 正文，就是为了躲开「本岗位非外包」这种反向表述。
真的被筛掉了，八成是**公司名或岗位名里**带了这两个字（比如公司叫「XX 外包服务有限公司」）。这时候去岗位详情看一眼确认下就好。

**Q：搜索框里敲「杭州 运营 15k」一条都没有，为什么？**
先看搜索框下面有没有一行小字「理解为：…」：
- **有**：说明解析成功了。一条都没有就真的是库里没这类岗位，试试点小字右边的「当普通关键词搜」放宽口径，
  或者确认下城市 / 薪资条件是不是定太死（`15k` 会被当成「薪资 ≥ 15K」，薪资为空的岗位仍然保留）。
- **没有**：说明它把这串当普通文字搜了 —— 而普通搜索是「整串连续匹配」，几乎搜不到。
  这种情况检查一下是不是点过「当普通关键词搜」（重新输入一次就会恢复解析）。

**Q：「🤖 按简历推荐」跑一半失败了 / 想停？**
单个岗位失败会**自动重试 1 次**；连续 3 个失败会停下来问你「继续 / 停」——一般撞上限流了，等几分钟再继续。
随时可以点取消，**已经评到的分不会丢**。重跑时默认跳过已评分的岗位，想全部重来就勾上「重新评分」。

**Q：匹配分跑完了，但「🏆 高匹配」胶囊是灰的 / 列表是空的？**
那个胶囊要**先有分**才有意义：分默认要 ≥ 80 才算「高匹配」。如果刚跑完还是空，说明这批岗位分数都不高，
属于正常结果（规则分和 AI 分都只是初筛，不等于录用概率）。胶囊右边那个小数字就是「点下去会剩几个」，
写 0 就别点了。

**Q：采集页说「没检测到本地采集器」？**
回工作台文件夹**双击 `启动采集器.cmd`**，等黑窗口出现内容，再回采集页点右上「🔄 重新检测」。
如果你本来就是双击 `index.html` 打开的，那属于正常情况——采集器没起时这一页会显示引导，其它功能不受影响。

**Q：不想用采集器，能用吗？**
能，而且功能一个不少。采集器的唯一价值是「一次捞一批」，省掉你一个个复制粘贴。没有它照样可以：粘贴导入、AI 解析、投递看板、面试管理、数据统计。

**Q：采集跑到一半卡住了 / 想停？**
回采集页点「■ 停止」。或者直接关掉那个黑窗口（会一起把采集进程和浏览器关掉）。
**别只关 Edge 窗口**——那会让采集脚本卡在等页面上。

**Q：采集完了但「采集结果」还是空的？**
1. 点「🔄 刷新结果」
2. 确认采集真的跑完了（日志末尾有成功提示）
3. 如果日志里报了错，多半是登录过期——重新点「登录 BOSS」扫一次码

**Q：在 `file://` 打开，采集页说「缺访问令牌」？**

这是**故意的**，不是坏了。采集接口只认**采集器打开的页面**（`http://127.0.0.1:8738/`）——
服务端启动时会生成一个随机令牌注入那个页面，`file://` 打开的同一份文件拿不到它。

为什么这么做：没有这道闸，你浏览器里**随便打开的任意网页**都能偷偷调 `127.0.0.1:8738`
读走你本机的岗位、简历画像，甚至往你磁盘写文件。「只监听 127.0.0.1」挡的是外网，**挡不住浏览器里的网页**。

**怎么办**：双击 `启动采集器`（或 `后台启动采集器.vbs`），在它打开的页面里用采集功能；
页面上的「🌐 打开采集器页面」按钮也能一键跳过去。其它所有功能（岗位库 / 投递 / 面试…）完全不受影响。

## 七、技术说明

- **零依赖**：没有 CDN、没有 npm 包、不联网也能打开（除了调 AI 那一瞬间）
  - 样式是手写的 CSS 设计系统（约 810 行），双主题用 `html[data-theme]` 切换
  - 图表是手绘 SVG（环形 / 柱状 / 漏斗 / 迷你折线），跟随主题取色
  - Excel 导出用 **SpreadsheetML 2003** XML，不需要任何库
  - 简历导出 PDF 走**浏览器打印**（打印对话框里「另存为 PDF」），Word 存带命名空间的 `.doc` —— 都不引第三方库
- **为什么用 `<script src>` 而不是 ES Module**：`file://` 下 `import` 会被 CORS 拦，普通 script 才能双击即用
- **AI 直连可行性**：实测 DeepSeek 会回显 `Origin: null` + `access-control-allow-origin: null`，所以 `file://` 页面能直接跨域调用
- **采集为什么需要一个小服务**：浏览器不能自己启动进程，也不能直接抓 zhipin.com。所以 `采集器/server.py` 只干一件事 —— 按网页的指令调起 `boss-crawler`，再把日志和结果回吐。
  - 它只监听 `127.0.0.1`（外网够不着），端口从 8738 起
  - 它同时**伺服工作台本体**，所以走 `http://127.0.0.1:8738/` 打开时是同源，连跨域都不需要
  - **访问控制（两道闸）**：
    1. **Origin 白名单** —— 跨源请求必须来自 `null` 或 `http://127.0.0.1:8738/8739/8740`，其它一律 403；
       响应头**只回显白名单里的那个 Origin**，不再用 `Access-Control-Allow-Origin: *`。
    2. **随机令牌** —— 服务启动时生成（落在 `采集器\data\token.txt`），并注入它 serve 的 `index.html`；
       所有 `/api/*` 都要带 `X-JH-Token`。攻击者能伪造 Origin，但拿不到令牌。
    > 为什么不能只靠「只监听 127.0.0.1」：服务确实只绑本机，但**攻击面是浏览器** ——
    > 你浏览器里打开的任意网页都能对 `127.0.0.1:8738` 发请求。以前 CORS 是 `*`，等于把
    > `/api/ping`（姓名 / 学历 / 期望薪资）、`/api/jobs`（全部岗位，含 HR 姓名）敞给任意网页读，
    > 还能被诱导触发 `/api/crawl`、往磁盘写 `/api/resume`。现在这两道闸把这条路堵死。
  - `GET /api/alive` 是唯一的免令牌接口，**只回「服务在跑、端口几号、PID 几号」，不含任何敏感信息** —— 给启动脚本判断「是不是已经在运行」用
  - **端口冲突会真的换一个**：用 `connect()` 试连判断端口占用。**不能**用 `bind + SO_REUSEADDR` ——
    Windows 上那等于「抢占一个正在被监听的端口」，会起出第二个**沉默僵尸**（进程活着、端口占着、页面打不开）。
  - **拒绝时也给得出原因**：403 的响应体是完整 JSON（`{ok:false, error, needToken}`）；
    前端「缺访问令牌」引导卡就靠 `needToken` 字段。真机测试里有断言盯着「`Content-Length` == 实际字节数」，
    专门防「响应体被截断、前端只看到网络错误」。
  - 采集前会**预检登录态**（45 分钟内检测过才算新鲜）：未检测 / 已过期 → 先让你扫码，避免白跑十几分钟
  - 全程只用 Python 标准库，没有额外依赖

所以把每条新功能**故意改坏一次**（比如把「批量只广播一次」改成逐条广播、把 `.bbar` 的样式删掉、把 ✕ 改回 `onclick: close`），

> 它同时会抓「锚点失效」：如果某处代码被改过、导致 `from` 片段找不到了，会明确报「锚点失效」并计入漏掉 ——
> 不这样做的话，"跳过"和"通过"看起来一模一样，很容易被骗过去。
> 锚点比对前会**把换行符归一化**：本项目的 js 文件 CRLF / LF 不统一，锚点里带 `\n` 会时灵时不灵。
> 改完代码跑完 ①② 后顺手跑一次 ③，能挡掉「加了功能但没加测试」这种情况。

> ⚠️ **改 `openModal` / 任何弹窗按钮回调时，务必两条规矩同时守**：
> ① 按钮回调**先落值再关窗**（`done(值); c();`）；② `openModal.close()` 里的 `onClose` **必须异步**触发。
> 曾经因为 `onClose` 同步执行、把按钮的 `resolve(成功值)` 抢先覆盖成 `resolve(null)`，
> 导致**七个功能全部静默失效**（删除岗位、新建面试、打招呼选岗位、对比加岗位、投递绑简历、清空数据、导入覆盖）——
> 表现就是「点了确认完全没反应」。这类 bug 只有真去点按钮才测得出来。
>
> 另一条同样致命的约定：**数据变了只许「就地重画对应节点」，绝不调 `App.refresh()`** ——
> 在渲染过程中再触发一次全页刷新会无限循环，页面直接卡死。

> `job-match.js` 同时被岗位库和采集页用（所以筛选规则只有一份，两处口径不会跑偏），
> `job-picker.js` 同时被采集页的「岗位期望」和设置页的「期望岗位」用，
> `geo.js` 是地理三级筛选的单一来源，`company-check.js` 是背调分级引擎（`view-company.js` 和岗位卡片的挂灯都调它）。
> 所以「十一个页面」对应的是 11 个 `view-*.js`。
