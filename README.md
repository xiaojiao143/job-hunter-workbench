# 求职猎手工作台 · Job Hunter Workbench

> 一个**本地优先、零安装**的求职管理工具。把你的求职过程当成一个项目来管理：岗位库、投递看板、面试管理、公司背调、AI 简历匹配、数据仪表盘。
>
> **数据只存在你自己的浏览器里**（localStorage），没有账号、没有云端、没有上传。

## 为什么会有这个项目

2026 年找工作时，我同时在跟 200+ 个岗位：有的投了没回音、有的约了面试、有的要背调、有的聊到一半失联。用 Excel 管，三周就崩了——状态不同步、不知道哪个该催、忘了为什么排除某家。

市面上的求职管理工具要么要注册账号把你的简历传上去，要么就是个看板没有别的。所以我想要一个**只属于我自己的、离线的、能一直用下去**的东西。

于是有了这个项目。它解决三件事：

1. **别丢** —— 岗位和投递状态不会因为换电脑/清缓存/误删而消失（导出即备份）
2. **别忘** —— 哪个该催、哪个该复盘、哪个面试明天到，打开就知道
3. **别瞎投** —— 投之前先看合适度和背调，把时间花在值得的岗位上

## 60 秒跑起来

**唯一前提：一个现代浏览器。** 不需要 Node、不需要 Python、不需要装任何东西。

```bash
git clone https://github.com/xiaojiao143/job-hunter-workbench.git
```

然后**双击** `求职猎手工作台/index.html`。

就这样。它能直接从 `file://` 跑起来——这是刻意的设计（见 [为什么不用框架](#为什么不用框架)）。

### 想先看看长什么样？导入示例数据

1. 打开工作台 → 右上角 **设置**
2. 找到 **数据备份** → **导入**
3. 选 `求职猎手工作台/demo-data/demo-backup.json`

里面有 6 条虚构岗位、2 条投递、1 场面试、1 份简历素材，用来体验各页面。**全部是假数据**。

### 可选：启动本地采集器（需要 Python）

```bash
cd 求职猎手工作台
python 采集器/server.py
```

然后浏览器打开 `http://127.0.0.1:8738/`。

> ⚠️ 采集器是**可选组件**，不启动也能用全部核心功能（手工录入、CSV 导入、看板、AI 匹配）。
> 使用前请阅读下方 [合规与免责](#合规与免责)。

## 技术栈与设计决策

| 层 | 选型 | 备注 |
|---|---|---|
| 前端 | **手写 ES5+ 原生 JS**，32 个模块 / 25,081 行 | 无框架、无构建、无 npm |
| 样式 | 手写 CSS，1,529 行，`:root` 令牌体系 | 无 Tailwind，保证离线可用 |
| 存储 | 浏览器 `localStorage` | 多账号用命名空间隔离 |
| 后端（可选） | Python 3 标准库 HTTP 服务，3,071 行 | 无第三方 Web 框架 |
| 测试 | Node + 自建 DOM 桩，**2,470 条断言** | 不开浏览器就能测 DOM 渲染 |
| 变异测试 | **298 条变异锚点** | 故意改坏代码，验证测试是否变红 |

### 为什么不用框架

这是本项目最重要的一个权衡，所以单独说明。

**目标约束**：双击 `index.html` 就要能跑。要支持 `file://`、离线、无安装、无 Node 环境。

**这个约束排除了什么**：任何需要构建步骤的方案（React/Vue + Vite/Webpack）。因为构建产物要么得提交到仓库（那还不如直接写 JS），要么得让用户装 Node 再 build（那就违反了"零安装"）。

**我为此付出了什么**：
- 没有组件复用 → 自建 `el()` DOM 工厂函数
- 没有响应式 → 每次数据变更手动 `App.go()` 整页重画，弹窗内只就地重画
- 没有状态管理 → 手写 `store.js`：归一白名单 + 迁移函数 + 事件订阅
- 没有 TS 类型检查 → 用运行时断言（2,470 条测试）兜底字段契约
- 重画会丢焦点 → 自建 `[data-focus-key]` 焦点保持机制

**如果重来会怎样**：如果这个项目要多人协作或长期演进，我会换成 Vite + TypeScript。**框架的价值在协作和规模，不在单人小工具**。当前选择是因为约束优先，不是因为不会用框架。

详见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 项目结构

```
.
├── 求职猎手工作台/          # 应用本体（双击 index.html 即可运行）
│   ├── index.html
│   ├── js/                  # 32 个模块：store/utils/components/ai + 12 个页面 + 能力模块
│   ├── css/app.css
│   ├── demo-data/           # 示例数据（全虚构）
│   ├── 采集器/server.py      # 可选：本地采集服务
│   ├── _测试_核心.js          # 2,470 条核心测试
│   ├── _回退自证.js           # 298 条变异测试
│   └── docs/
└── _打包工程/               # 打包为 exe 的工装（PyInstaller）
    ├── sync_src.py          # 前端副本同步 + 一致性闸门
    ├── pack_main.py         # 出包主流程（含双重闸门）
    ├── src/                 # 打包用的前端副本 + 服务端核心
    └── crawler_src/         # 采集组件源码
```

> 目录名带下划线前缀（`_测试_`、`_回退自证`、`_打包工程`）是刻意保留的历史约定：静态服务会拒绝伺服下划线开头的文件，避免测试脚本被当成可访问资源。

## 测试

```bash
cd 求职猎手工作台
node _测试_核心.js
```

预期输出：`✅ 全部通过（2470 项）`

**这套测试的几个不常见之处**（也是我最想让面试官看的部分）：
- **不开浏览器测 DOM**：自建 DOM 桩，把 32 个模块按 `index.html` 的顺序加载，真渲染 12 个页面
- **断言里写历史事故**：每条重要断言旁边注明"这里以前踩过什么坑"，测试同时是事故档案
- **变异测试**：`_回退自证.js` 里有 298 条"故意把代码改坏"的锚点，用来验证测试真能发现问题（防止测试假绿）

详见 [docs/TESTING.md](docs/TESTING.md)。

## 合规与免责

本项目是**个人求职管理工具**，不是数据采集服务。

- **数据归属**：所有岗位、简历、笔记只存在你本地浏览器的 `localStorage` 里。项目不含、也不上传任何平台数据。
- **采集组件**：`采集器/` 与 `_打包工程/crawler_src/` 是可选组件，仅用于**你自己账号下**的岗位信息整理。默认不启用，核心功能不依赖它。
- **使用责任**：若你启用采集功能，请自行确认目标网站的服务条款与当地法律法规。**使用者自行承担全部责任**，作者不对使用后果负责。
- **无数据分发**：本仓库不包含任何真实公司信息、HR 联系方式、简历文件或采集结果。`demo-data/` 内容全部虚构。
- **AI 功能**：需要你自己配置模型 API Key，请求直接发往你配置的服务商，不经过本项目服务器。

## 已知限制

诚实列在这里，比藏着强：

1. **不支持多设备同步** —— 这是"本地优先"的代价。换设备靠手动导出/导入 JSON。
2. **数据量上限受 localStorage 限制**（通常 5MB）—— 大约能放 2,000-3,000 条岗位。超过后用导出分库。
3. **AI 功能需要自备 API Key** —— 不配置也能用，只是没有 AI 解析/匹配/话术。
4. **采集功能依赖目标网站的页面结构** —— 网站改版后会失效，需要更新选择器。
5. **不保证跨浏览器的 localStorage 数据格式兼容** —— 导出 JSON 是跨浏览器迁移的正路。
6. **移动端只做了基础适配** —— 主要面向桌面浏览器（求职时用电脑更多）。
